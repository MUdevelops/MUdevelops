```mermaid
flowchart TD
    U([User / Real Problem]) --> UI[Product Interface]
    UI --> API[Application & API Layer]
    API --> AI[LLM · RAG · AI Agents]
    API --> DB[(SQL / Vector Data)]
    DB --> AI
    AI --> ACT[Useful Answer or Action]
    ACT --> U
    classDef user fill:#101a2e,stroke:#33d3ff,color:#f2f7ff,stroke-width:2px
    classDef app fill:#17152f,stroke:#9b8cff,color:#f2f0ff,stroke-width:1.5px

    class UI,API,AI app
    class DB data
```

## 05 / Build philosophy

<table>
  <tr>
    <td width="50%" valign="top"><strong>01 — Solve a real problem</strong><br />Start with the user and the reason the software should exist.</td>
    <td width="50%" valign="top"><strong>02 — Engineer the whole system</strong><br />Connect the interface, logic, data, and AI instead of treating them as isolated pieces.</td>
  </tr>
  <tr>
    <td width="50%" valign="top"><strong>03 — Verify what you build</strong><br />Test behavior, handle failure cases, and improve what actually matters.</td>
    <td width="50%" valign="top"><strong>04 — Ship and iterate</strong><br />A useful working product beats an impressive unfinished prototype.</td>
  </tr>
</table>
